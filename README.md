# Meridian Online — лаунчер

Официальный лаунчер CRMP-проекта **Meridian Online**: устанавливает игру, обновляет её и лаунчер, показывает онлайн сервера и подключает к **80.242.59.112:2557** одной кнопкой.

Electron 38 · без фреймворков · Windows x64.

## Возможности

- **Установка игры в один клик**: загрузка с докачкой и паузой, проверка SHA-256, распаковка 7-Zip, проверка свободного места и прав на папку.
- **Обновления игры**: новая сборка из `game/manifest.json` скачивается автоматически (это отключается в настройках).
- **Автообновление лаунчера** через GitHub Releases: при запуске заставка проверяет новую версию, скачивает её и перезапускает лаунчер. Пока лаунчер открыт, проверка повторяется каждые 30 минут.
- **Вход на сервер**: ник и путь к игре записываются в `HKCU\Software\SAMP`, затем запускается `samp.exe 80.242.59.112:2557`. Если `samp.exe` в сборке нет, игра запускается так: `gta_sa.exe -c -n Ник -h IP -p PORT`.
- **DirectX, Visual C++ и DirectPlay**: перед запуском лаунчер проверяет компоненты, которые нужны сборке (DirectX 9.0c, Visual C++ 2010 и 2015–2022 x86, компонент Windows DirectPlay), скачивает официальные установщики Microsoft, включает DirectPlay через DISM и всё делает тихо, с одним запросом прав администратора. То же делается сразу после установки игры и кнопкой в настройках.
- **Живой онлайн и пинг** сервера по query-протоколу SA-MP/CR-MP.
- **Контент без перевыпуска**: новости, слайды, ссылки, соцсети, FAQ и список серверов лежат в `content/launcher.json` и подтягиваются из ветки `main`.
- Свой вариант уже установленной игры указывается кнопкой «Уже есть игра».
- Трей, сворачивание после запуска игры, анимированный фон (снег, туман, параллакс), который можно выключить.

```

.github/workflows/game.yml     публикация сборки игры
```

## Разработка

```bash
npm install
npm start          # запуск лаунчера
npm run dev        # с DevTools
npm run dist       # собрать установщик локально (Windows) → dist/
```

Дизайн можно смотреть и в обычном браузере: запустите в корне статический сервер (например `npx serve`) и откройте `src/renderer/index.html?s=ready`. Состояния: `ready`, `download`, `update`, `install`, `welcome`. В браузере вместо API лаунчера работает заглушка `js/mock.js`.

## Как выпустить новую версию лаунчера

1. Поднимите `"version"` в `package.json` (например `1.0.0` → `1.0.1`).
2. Залейте изменения в `main`.
3. GitHub Actions соберёт `MeridianOnline-Setup-1.0.1.exe` и опубликует релиз `v1.0.1`.
4. У игроков лаунчер обновится сам при следующем запуске.

Новых игроков отправляйте на установщик со страницы последнего релиза: `https://github.com/FluffyBarbara/meridianonline/releases/latest`.

## Как опубликовать игру (или её обновление)

Сборка весит больше гигабайта, а GitHub не принимает в ветку файлы больше 100 МБ. Поэтому игра раздаётся через GitHub Releases: до 2 ГБ на файл, общий объём не ограничен.

### Автоматически, через Google Drive (рекомендуется)

1. Загрузите `.rar` с папкой игры на Google Drive и откройте доступ «всем, у кого есть ссылка».
2. Впишите ссылку и **новую** версию в `game/source.json`.
3. Залейте изменение. GitHub Actions (`Publish game build`) скачает архив, перепакует его в 7z-тома, опубликует pre-release `game-<версия>` и сам закоммитит `game/manifest.json`.

После того как манифест попадёт в `main`, лаунчеры игроков предложат обновление.

### Вручную, со своего компьютера

```bash
npm install
npm run pack-game -- --src "E:\Meridian\Meridian Online" --version 1.0.0
```

Скрипт упакует папку с игрой (где лежит `gta_sa.exe`) в `dist-game/MeridianOnline-1.0.0.7z.001, .002, …` и обновит `game/manifest.json`. Дальше:

1. На GitHub → **Releases → Draft a new release**, тег `game-1.0.0`.
2. Перетащите все тома из `dist-game/`, отметьте **Set as a pre-release** и опубликуйте. Отметка нужна, чтобы релиз игры не мешал автообновлению лаунчера.
3. Закоммитьте `game/manifest.json` в `main`.

Можно загрузить тома автоматически: создайте токен (Settings → Developer settings → Fine-grained token, право *Contents: write* на этот репозиторий) и выполните:

```powershell
$env:GITHUB_TOKEN="ваш_токен"
npm run pack-game -- --src "E:\Meridian\Meridian Online" --version 1.0.0 --upload
```

Если файлы хранятся на своём сервере, добавьте `--base-url https://ваш-сайт/files`.

## Новости, ссылки, слайды

Отредактируйте `content/launcher.json` в `main`, и лаунчеры подхватят изменения (через raw.githubusercontent.com, а если он заблокирован — через GitHub API или jsDelivr) при следующем запуске (и раз в 10 минут, пока открыты). Ссылки на форум и магазин задаются в `links`. Фон можно заменить своим артом: положите `src/renderer/assets/background.jpg` или укажите URL в поле `"background"`.

## Параметры запуска игры

Список `prerequisites` в `game/manifest.json` задаёт, какие компоненты Windows ставить: `directx`, `directplay`, `vc2008`, `vc2010`, `vc2012`, `vc2013`, `vc2015`.

Блок `launch` в `game/manifest.json` определяет, какой exe запускать, с какими аргументами и что записывать в реестр. Плейсхолдеры: `{ip}`, `{port}`, `{nick}`, `{gameDir}`.

## Статус в Discord

Статус в Discord по умолчанию выключен: игрок включает его в настройках лаунчера («Статус в Discord»). Лаунчер показывает в профиле Discord «Играет в Meridian Online» с текстом «Смотрит лаунчер», а когда запущена игра — «Проводит время на Meridian Online | WHITE». Статус можно выключить в настройках лаунчера.

Чтобы статус заработал, нужно приложение Discord (один раз):

1. Откройте https://discord.com/developers/applications → **New Application**, назовите **Meridian Online**. Это имя Discord показывает в строке «Играет в …».
2. Скопируйте **Application ID** на странице General Information.
3. Впишите его в `content/launcher.json` → `discord.clientId` и залейте в `main`. Выпускать новую версию лаунчера не нужно: изменения подхватятся при следующем запуске и раз в 10 минут.

Тексты, картинка и кнопки статуса тоже настраиваются в блоке `discord` этого файла. `{server}` в `gameText` заменяется названием сервера.

## Фикс игры

Кнопка «Фикс игры» есть в сайдбаре, в «Поддержке» и в настройках. Если игра закрылась меньше чем через 2 минуты после запуска, лаунчер сам предложит её нажать. Что делает фикс:

1. Закрывает зависшие `gta_sa.exe` и `samp.exe`.
2. Проверяет все файлы сборки по `game/files.json` (размер и SHA-256). Файлы настроек и логи проверяются только на наличие. Если что-то повреждено или удалено, предлагает перекачать сборку.
3. Переносит в `_disabled_mods` посторонние `.asi`, `.dll`, `.cs` и `.cleo`, которых нет в сборке (читы, ENB, `d3d9.dll`).
4. Сбрасывает `Документы\GTA San Andreas User Files\gta_sa.set`, сохраняя копию рядом.
5. Снимает режимы совместимости с `gta_sa.exe` и `samp.exe`, отключает для игры оптимизацию во весь экран (`~ DISABLEDXMAXIMIZEDWINDOWEDMODE HIGHDPIAWARE`).
6. С одним запросом прав администратора: переустанавливает DirectX, Visual C++ и DirectPlay, добавляет папку игры в исключения Защитника Windows, снимает режимы совместимости «для всех пользователей».

`game/files.json` создаётся автоматически при упаковке сборки (`pack-game.js`, workflow «Publish game build»).

## Если игра вылетает

Когда игра закрывается быстрее чем за 2 минуты, лаунчер показывает три шага:

1. **Фикс игры** (см. выше).
2. **Безопасный запуск**: на время игры отключает графические моды, которые меняют видеорежим (`Multi-sampling fix.asi`, `RefreshRateFixByDarkP1xel32.ASI`, `sa_widescreenfix_lite.asi`, `RealSkybox.SA.asi`, `skygrad.asi`, `_colorsmoke.SA.asi`). Файлы переименовываются в `*.off` и возвращаются после выхода из игры. Список задаётся в `game/manifest.json` → `safeMode`. Включается и в настройках.
3. **Отчёт для поддержки**: сохраняет на рабочий стол файл `Meridian-отчёт-….txt` и копирует его текст в буфер обмена. В нём:
   - Windows, процессор, память, видеокарта и драйвер, экраны (разрешение, масштаб, частота);
   - компоненты, режимы совместимости, антивирусы, ключи SA-MP в реестре;
   - посторонние файлы в папке игры, содержимое `GTA San Andreas User Files`, параметры последнего запуска;
   - крэш-лог `fastman92limitAdjuster.log`, логи модов и CEF, лог лаунчера.

## Драйвер видеокарты

Самая частая причина вылета сразу после запуска: не установлен драйвер видеокарты, и Windows работает через «Базовый видеоадаптер (Майкрософт)» без аппаратного Direct3D. GTA не может создать графическое устройство, и `samp.dll` падает с `EXCEPTION_ACCESS_VIOLATION` по адресу `0x0`.

Лаунчер проверяет это сам (`src/main/gpu.js`):
- при старте и перед каждым запуском игры;
- в «Фиксе игры» и в «Отчёте для поддержки».

Производителя видеокарты он определяет по коду устройства (`VEN_10DE` — NVIDIA, `VEN_1002` — AMD, `VEN_8086` — Intel). Если драйвера нет, лаунчер показывает ссылку на драйвер нужного производителя и кнопку «Центр обновления Windows → Необязательные обновления».

## Интерфейс CEF (omp-cef)

Внутриигровой интерфейс работает на [omp-cef](https://github.com/aurora-mp/omp-cef). Сервер упаковывает папку `scriptfiles/cef/<ресурс>/` в зашифрованный `<ресурс>.pak`, клиент скачивает его в `Документы\GTA San Andreas User Files\cef\cache\<ip>_<port>\` и отдаёт файлы по адресу `http://cef/<ресурс>/<путь>`. Лог клиента: `Документы\GTA San Andreas User Files\cef\client.log`. Он попадает в «Отчёт для поддержки», а «Фикс игры» очищает кеш.

Если вместо интерфейса показывается `This site can't be reached … http://cef/assets/index.html ERR_FAILED`:

0. **Кириллица в пути к «Документам» у игрока — самая частая причина.** Так бывает при OneDrive на русской Windows (`C:\Users\nikit\OneDrive\Документы`) и при русском имени пользователя (`C:\Users\Никита`). Ошибка в самом omp-cef (`Gta::GetUserFilesPath`): путь в UTF-8 передаётся в `std::filesystem::path` как строка в кодировке CP1251. Клиент пишет кеш в папку `…\Р”РѕРєСѓРјРµРЅС‚С‹\…`, а `.pak` открывает по настоящему пути и не находит.

   Лаунчер обходит это (`src/main/game/cefpath.js`): перед запуском игры создаёт на месте «испорченной» папки ссылку (junction) на настоящую. Если для ссылки нужны права администратора (русское имя пользователя), её создаёт «Фикс игры». Не обходится только путь с заглавной «И»: в CP1251 у неё нет байта, и игроку нужен путь к «Документам» без этой буквы.

Если путь к «Документам» без кириллицы, значит, после загрузки `assets.pak` в нём не нашлось `index.html`:

1. **Структура.** На сервере должен лежать ровно `scriptfiles/cef/assets/index.html`, без лишней вложенной папки.
2. **Регистр букв.** Имя в `CEF_AddResource("assets")`, папка и путь в `CEF_CreateBrowser(..., "http://cef/assets/index.html", ...)` должны совпадать с учётом регистра.
3. **Ключ.** Если меняли `cef.master_resource_key` в `config.json` (или `cef_master_resource_key` в `server.cfg`), удалите `scriptfiles/cef/assets.pak` и `scriptfiles/cef/assets.pak.manifest` и перезапустите сервер. Сервер не замечает смену ключа и продолжает раздавать PAK, зашифрованный старым ключом, а клиент не может расшифровать `.html`, `.css` и `.js`. Ключ должен быть ровно 16, 24 или 32 байта; кириллица занимает по 2 байта на символ.
4. **Ограничения.** Файлы больше 20 МБ и с расширениями не из списка (`.html .css .js .json .xml .png .jpg .jpeg .gif .svg .ico .mp3 .ogg .wav .woff .woff2 .ttf .otf .eot`) сервер молча пропускает. Например, `.webp` и `.mp4` не попадут в PAK.

## Подробная активность в Discord

Пока идёт игра, лаунчер раз в 3 секунды читает состояние игрока из памяти `gta_sa.exe` (`src/main/game/memory.js`). Он только читает, в игру ничего не записывает и не внедряет. По этому состоянию строится статус (`src/main/game/presence.js`):

| Ситуация | Пример статуса |
|---|---|
| Пешком | «Стоит на месте», «Гуляет пешком», «Бежит», «Ранен, ищет помощь» |
| Машина | «За рулём ВАЗ 2101 · 90 км/ч», «Гоняет на BMW X5 · 160 км/ч», «Сидит в Лада Калина», «Пассажир в …» |
| Служебный транспорт | «Патрулирует / Преследует на Машина полиции», «Спешит на вызов · Скорая помощь», «Едет на пожар», «Таксует на ГАЗ-2401 Такси», «Везёт пассажиров · ЛиАЗ-677М», «Дальнобойщик · ЗиЛ-133», «Эвакуирует машины», «Вывозит мусор», «Работает в поле» |
| Другой транспорт | «Едет / Гоняет на Иж планета 5», «Катается на велосипеде», «Пилотирует Ми-24», «Плывёт на …», «Ведёт поезд ЭД4М» |
| Прочее | «В помещении», «В меню паузы», «Свернул игру», «Отошёл от компьютера (AFK)», «Без сознания», «Заходит на сервер…» |

- Вторая строка статуса — район: «📍 Арзамас · WHITE».
- Маленький значок показывает вид активности (`content/discord/*.png`).
- Счётчик группы показывает онлайн сервера, например «187 из 500».
- Названия 321 машины взяты из `american.gxt` сборки (`src/main/game/vehicles.json`).

Всё настраивается в `content/launcher.json` → `discord.presence` без выпуска лаунчера:

- `zones` — районы карты: `{"name": "Арзамас", "min": [x1, y1], "max": [x2, y2]}`. Если районы вложены, выбирается самый маленький. Для района можно задать свой текст:
  - `"text"` — когда игрок пешком, например `"Сдаёт на права"`;
  - `"vehicleText"` — когда в машине, например `"Таксует по {zone} на {vehicle}"`.
- `defaultRegion` — что писать вне всех районов (по умолчанию «Нижегородская обл.»).
- `showCoords: true` — временно показывать в Discord координаты вместо района, чтобы разметить районы: встаньте в углы города и запишите `x` и `y`.
- `vehicles` — переопределить машину: `{"404": {"name": "Копейка", "role": "taxi", "text": "Бомбит на {vehicle}"}}`. Роли: `police`, `ambulance`, `fire`, `taxi`, `bus`, `truck`, `tow`, `trash`, `tractor`.
- `showSpeed`, `showOnline` — скорость в статусе и онлайн сервера.

## Онлайн сервера

Онлайн берётся UDP-запросом SA-MP query (opcode `i`) с повторами. Если сервер не отвечает на query (query отключён или работает на другом порту), лаунчер пишет не «Сервер недоступен», а «Онлайн неизвестен · можно играть» — войти в игру всё равно можно. У сервера в `content/launcher.json` можно задать:

- `"queryPort"` — если SA-MP query слушает другой порт (не игровой);
- `"statusUrl"` — HTTP-адрес, отдающий JSON с онлайном (`{"online": N, "max": M}` и похожие поля). Нужен, если query на сервере выключен и UDP-запрос не ответит.

## Защита кода (обфускация)

Перед упаковкой `scripts/bundle.js`:

1. **esbuild** собирает каждый процесс (main, preload, renderer) в один файл, втягивая все локальные модули. В установщике нет отдельных `config.js`, `query.js`, `presence.js` и т.д. — только три бандла.
2. **javascript-obfuscator** обфусцирует их: переименование идентификаторов, строки в закодированный массив, control-flow flattening. IP сервера, адреса и логика в читаемом виде в сборку не попадают.

Результат кладётся в `dist-app/`, его и упаковывает electron-builder (`files → from: dist-app/src`). Исходники `src/**` в установщик не включаются. Публичные ключи API (`window.meridian.*`) не обфусцируются — они нужны для связи процессов. Сборка запускается сама: `npm run dist` (локально) или `npm run release` (в CI).
